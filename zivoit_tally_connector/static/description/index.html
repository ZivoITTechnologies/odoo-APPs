1. Dashboard: every Tally connection at a glance

  • Run as many Tally companies as you need (head office, branches), each with its own settings.
  • Live counters: synced today, queued, failed, vouchers to review.
  • Sync now, Test and Mappings are one click away.
  • An auto-sync runs every 2 minutes, and multi-company is supported.

2. Connection, scope and AI health check

  • Choose the direction separately for parties, ledgers, items, each voucher family and cost centres: Tally to Odoo, Odoo to Tally, or two-way.
  • Supports both the TallyPrime 3.0+ XML schema and the legacy Tally.ERP 9 schema.
  • The AI health check summarises failures, vouchers to review, unmapped masters and balance differences.
  • Buttons for Reconcile balances, Detect deletions and Full re-sync.

3. Bridge Agent for Odoo Online & Odoo.sh

  • A small Python agent runs on the Tally PC and only makes outbound HTTPS calls to Odoo.
  • No static IP, VPN or port forwarding is needed.
  • It uses Odoo's standard API key and a per-connection token.
  • Download agent package gives you a pre-filled config and a Windows service installer.
  • The connection shows whether the agent is online and whether it can reach Tally.

4. AI master matching, with the reason shown

  • Matches on GSTIN (checksum-validated), same PAN in another state, e-mail and phone, part number and HSN.
  • Name matching understands M/s., Pvt Ltd and common abbreviations.
  • Confident matches are confirmed automatically. Unclear ones are left as suggestions for you to confirm.
  • An LLM is optional (Claude, OpenAI, Gemini or Ollama) and is only asked about unclear matches. It is sent names only.
  • Masters not found in Odoo are created automatically: contacts, products, analytic accounts and locations.

5. Vouchers from Tally: staged, checked, posted

  • Only new or changed vouchers are read, using Tally's AlterID.
  • Item invoices become Odoo invoices with your Odoo taxes. Other vouchers are imported as exact journal entries.
  • Custom voucher types (e.g. "GST Sales") are recognised automatically.
  • "Agst Ref" bill allocations reconcile receipts and payments with their invoices.
  • Each voucher gets a risk score and a clear status.

6. AI anomaly guard, in both directions

Every voucher is checked before it is posted in Odoo or sent to Tally. Blocking findings hold the voucher and explain why. An accountant can review and override.

7. Conflicts and deletions handled safely

Altered in Tally after import? Choose Apply Tally version or Keep Odoo version, or set a policy: hold for review, Tally wins or Odoo wins. A conflict is only raised when the synced values actually differ, not when Odoo merely touched the record.

Deleted in Tally? Tally does not report deletions, so a lightweight scheduled check finds them for vouchers, ledgers and items. The Odoo entry is cancelled and its stock reversed, or kept, depending on your policy. A mass-deletion guard changes nothing if too much disappears at once.

8. Godowns, batches and real stock moves

  • Tally godowns become Odoo locations: "Main Location" maps to warehouse stock, and new godowns are created as locations.
  • Tally batches become Odoo lots/serials, including expiry dates. Tracked products are created in Tally with "Maintain in batches" switched on.
  • Sales, purchases and credit/debit notes from Tally create and validate the delivery, receipt or return in the right godowns and lots. The example above shows 3 drums from WH/Stock lot PD-2610-A and 2 from Hyderabad WH lot PD-2610-B.
  • From Odoo to Tally: invoice lines carry the real godown and lot split from the delivery. If a voucher is altered, cancelled or deleted, its stock is reversed.

9. Cost centres and analytic accounts

A Tally payment split 30,000 / 18,000 across cost centres becomes a 62.5% / 37.5% analytic distribution in Odoo.

An Odoo invoice split 50% / 50% becomes Tally cost-centre allocations on the same voucher.

10. Full audit log and self-healing

  • Every request and response is kept as XML, with timing and counts.
  • Masters are always sent before vouchers. Failures retry with back-off.
  • The Error doctor turns Tally error messages into plain fixes, and missing masters are created and retried automatically.

11. Party balance reconciliation

  • Compares each party's closing balance in Tally with Odoo.
  • Flags parties that exist on only one side and suggests the likely cause of each difference.

12. Tally status on every invoice

  • Shows whether each document is In Tally, From Tally, Queued, Held by AI guard, Tally error or Deleted in Tally.
  • Invoices push automatically when posted. Re-posting updates the same Tally voucher instead of creating a duplicate.
  • Vouchers that came from Tally are never sent back to it.
  • Push to Tally is also available as a bulk action on invoices, contacts and products.

Live in about 10 minutes

  1. TallyPrime: F1 > Settings > Connectivity > TallyPrime acts as = Both, port 9000. Keep the company open.
  2. Odoo: install the app, open Tally > Configuration > Connections > New, enter the exact Tally company name.
  3. Pick a transport. Direct if Odoo can reach the Tally PC. Bridge Agent for Odoo Online or Odoo.sh: click Download agent package, unzip it on the Tally PC, paste an API key and run the installer.
  4. Click Test connection, then Sync now.
  5. Review Mappings (AI pre-fills them) and Vouchers from Tally. Optionally run Historical migration with a dry run first.

AI settings: the built-in engine works offline. An LLM provider is optional, and amounts are only shared if you allow it.

FAQ

Does it work with Odoo Online?
Yes. Odoo Online cannot reach a PC in your office, so the Bridge Agent on the Tally computer connects outward to Odoo over HTTPS and relays the requests.

Will vouchers be duplicated if I re-post an invoice?
No. Each Odoo document has a stable Tally ID, so re-posting alters the same Tally voucher. Vouchers that came from Tally are never pushed back.

Is an AI subscription required?
No. Matching, the GST guard, the error doctor and reconciliation all run inside Odoo. An LLM is optional and only used for unclear matches and plain-language explanations.

What happens if Tally is closed?
Requests wait in the queue and retry with back-off, and nothing is lost. Posting in Odoo never fails because Tally is unavailable.

Can I bring in past years?
Yes. Use Tools > Historical migration in either direction for any date range. A dry run shows what would happen first.

What is not covered?
Stock and manufacturing journals, and delivery or receipt notes that have no invoice in Tally. Deletion checks run on a schedule (default every 6 hours), not instantly.
